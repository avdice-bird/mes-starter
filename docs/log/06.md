# 第 06 节 · RBAC · 【建】用户 / 角色 / 权限 / 菜单

- 日期：2026-09-18
- 目标：四张表跑通，`@Permissions` 守卫生效，前端按权限渲染菜单
- 用时：课内 40 分钟 / 课外约 120 分钟

## 我做了

- 定了权限码全集（15 个）与 5 个种子角色、5 个种子用户、菜单树（`prisma/rbac-data.ts`）——这是前后端共同语言，先定码再生成代码
- 做了三个设计判断：
  1. **Menu 增加 `component` 字段**（任务卡字段清单之外）：动态路由需要"菜单 → 组件"映射，按路径约定太脆，显式存库里；
  2. **Menu.path 唯一**：既是路由唯一性保证，也让 seed 的 upsert 有 key；
  3. **权限码字典只读**：`/permissions` 不开放增删——代码里写死的 `@Permissions` 码必须先入种子表，否则扫描测试不过。
- 实测验收（见 docs/acceptance/rbac.md）：admin 登录 15 个权限码 + 4 个菜单；planner 菜单为空、调 `POST /api/users` 得 403（curl 实测 + 无头浏览器截图对比两个角色的侧栏）

## AI 做了

- 一次分层生成：schema → 4 个后端模块 → 守卫 → 前端四页，返工 3 次：
  1. `QueryUserDto extends PageQuery`：PageQuery 是 interface，class 不能 extends → 改为服务端 `PageQueryDto` 基类；
  2. 无角色用户的菜单树返回了空的「系统管理」目录 → `visibleTree` 加空目录剪枝；
  3. 矩阵测试里用户名 `matrix-user` 不符合自己的正则 → 改 `matrix_user`（AI 定的正则连自己的测试数据都不满足）。

## 发现的问题

- 双重守卫：AuthController 原来自己挂 `JwtAuthGuard`，全局守卫注册后会跑两遍 validate（两次查库）→ 删掉 Controller 级的
- `nest-cli.json deleteOutDir: true` 在本机会触发 safe-delete hook（第二次启动必挂）→ 关闭
