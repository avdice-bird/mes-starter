# 派工与工序流转验收标准（第 34-36 节）

| # | 验收项 | 验证方式 | 结果 |
|---|---|---|---|
| 1 | 下达生成任务快照 | `release` 事务内复制 ACTIVE 路线工序：任务数 = 工序数，第一道 READY 其余 PENDING | ✅ |
| 2 | 路线快照不变量 | 下达后激活新版本路线，已下达工单的任务不变（任务行是快照，无外键指向路线） | ✅ |
| 3 | 派工 | `POST /work-order-operations/:id/assign`：班组/员工/设备；设备必须属于工序工作中心；员工需技能且在职 | ✅ |
| 4 | 开工 | READY → IN_PROGRESS；首道开工时工单自动转 IN_PROGRESS（同事务写状态 log）；PENDING 开工 2004 | ✅ |
| 5 | 数量流转不变量 | 下道 plannedQty ≤ 上道良品数；上道完工时下道 plannedQty 动态下调并转 READY | ✅ |
| 6 | 末道完工 | 工单 completedQty 回写、complete 出现在 allowedActions（前端置由 `assertAllOperationsDone` 校验） | ✅ |
| 7 | 临时完工接口 | `POST :id/complete-qty`（第 37 节删除，由报工替代） | ✅→已删 |
| 8 | 权限 | `work-order-operation:view/assign/start`，planner 全有 | ✅ |
| 9 | 前端工序任务表 | 工单详情抽屉：seq/名称/工作中心/状态/数量/派工/操作；派工弹窗按工作中心过滤班组与设备 | ✅ |

第 35 节边界决策（任务卡要求写明）：

- **用例 5（数量策略）**：下达时全部任务 plannedQty = 工单 qty；上道完工时**动态下调**下道 plannedQty 为 min(上道良品, 工单 qty)。理由：派工时工人看的是"这道实际要做什么数量"，静态全量会导致后道白等不会来的数量；且下发补齐由流转函数统一算，不散落。
- **用例 6（技能）**：选择**拒绝**（非警告强制）：技能数据第 23 节已有，拒绝成本为零；错误消息明确指出缺哪道工序的技能。员工无任何技能记录时放行（新员工未录技能，只警告场景留给以后）。
