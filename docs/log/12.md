# 第 12 节 · 审计日志 · 【建+测】用模板 v2 生成审计日志，跑 M1

- 日期：2026-09-20
- 目标：审计日志模块 + 自动记录写操作的拦截器；课末跑 M1 验收脚本
- 用时：课内 40 分钟 / 课外约 90 分钟

## 我做了

- **模板只读开关（v2.1）**：任务卡预判正确——模板为 CRUD 设计，不支持"只有查询"的模块。在「输入」段加了 `模块形态：完整 CRUD / 只读` 开关，标注 `<!-- v2.1 -->`：只读模块只生成 list+详情接口与 `前缀:view` 权限码，省略 Form 与变更类矩阵行。
- 两个设计判断：
  1. **审计层先于异常过滤器拿到原始异常**：P2002 不会被转成 1005——拦截器里复用 `isPrismaUniqueViolation` 做同样翻译，审计读者看到的是业务语义（1005）而不是 Prisma 码。这是 e2e 用例 4 抓出来的（期望 1005 实得 P2002）。
  2. **审计写入异步、失败不阻塞业务**：`void this.write()` + try/catch 吞错打日志。代价：写入比响应晚，e2e 需轮询等待（`waitForAudit` helper）——如果审计要求强一致，改成同步写会拖慢每个写请求。
- username 记快照而非关联 userId：用户改名/删除后历史审计仍可读。

## AI 做了

- 按模板（只读开关）生成：schema/migration、AuditService/Controller（list + 详情，sortBy 白名单）、`AuditInterceptor`（全局注册、`@SkipAudit()`、密码/token 脱敏、module/action 解析、成功与失败都记录）、前端 api + AuditList 页（结果按错误码筛选）。
- e2e 4 例 + 矩阵 3 行。
