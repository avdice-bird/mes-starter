## 二、本次新增攻击用例与结果

### A. JWT 伪造与双 token 混用（10 例，全过）

| # | 攻击 | 结果 |
|---|---|---|
| 1 | 对照：未篡改的真实 token | 200 ✓（证明不是无脑全拒） |
| 2 | 篡改 payload.sub 为别人 id、保留原签名 | 401（code 1002）✓ |
| 3 | 篡改 payload 塞 `role:admin`/`permissions:*` 声明 | 401 ✓（且后端根本不读这些声明） |
| 4 | 错误密钥自签、合法结构、带管理员声明 | 401 ✓ |
| 5 | `alg:none` 空签名 | 401 ✓（算法白名单） |
| 6 | 签名合法但 sub 指向不存在用户 | 401 ✓（每请求查库） |
| 7 | 空 Bearer / 裸 token / 垃圾串 | 全 401 ✓ |
| 8 | refresh token 当 access token 打业务接口 | 401 ✓（双 token 不混用） |
| 9 | access token 当 refresh token 换新 | 400 拒（JWT 超过 refresh DTO 128 位上限）✓，响应无新 token 对 |
| 10 | 伪造信任头 `X-User-Id` / `X-Forwarded-User` | 仍 401 ✓（后端不信任请求头） |

### B. 匿名全路由扫描（2 例，全过）

从源码逐行状态机收集全部 Controller 路由（共 179 条）：

- `@Public` 路由集合**恰为** `GET /api/health`、`POST /api/auth/login`、`POST /api/auth/refresh` 三条，多一个或少一个都失败（防止 `@Public` 标错方法被悄悄带上线）✓
- 匿名探测其余 176 条路由：一律 401，**不允许 404/500**（404 会泄漏路由存在性，500 泄漏内部异常）✓

### C. 垂直矩阵缺口模块（40 例，全过）

`permissions-matrix` 未覆盖的模块，按"低权 403 精确断言 + 有权方对照（过守卫即可）"补齐：

| 模块 | 验证 |
|---|---|
| inventory | balances/adjust/领料生成/入库：planner 200/过守卫，qc、operator、maintainer 403 |
| inspection | 列表 qc 200，operator/maintainer 403；提交检验 operator 403 |
| andon | 列表 operator 200（有 andon:view，发起呼叫合法）；respond/close operator 403 |
| board | summary planner 200，operator/qc 403 |
| notifications | 五角色均有 notification:view，全 200；标记已读过守卫 |
| dispatch（工序） | 原报告结论为 operator 全 403；**2026-10-30 起** operator 持有 `work-order-operation:view/start`（见文件头说明与 permissions-matrix.e2e-spec.ts），view/派工读取按新权限放行，越权写入仍被 403 |
| equipment-status/downtime | maintainer 专管，qc 403，maintainer 过守卫 |
| reports / attachments / ai | 低权 403；ai 有权方不在此验证（涉及外部调用） |

### D. 提权语义（2 例，全过）

- operator 对**自己的 id** `PUT /users/:id/roles` 分配 admin 角色 → 403（先被 `user:assign-role` 拦下），且库中未提上权 ✓
- qc PATCH 自己的资料 → 403，库中未改 ✓

## 三、水平越权说明

本系统是单工厂模型，业务数据全局共享（有 view 码即可读任意 id），横向敏感面集中在报工/派工的**班组归属**：

- 报工篡改 `employeeId` 为别班组员工 → 400 拦截（既有 `attack-report` 攻击 4 覆盖）✓
- 派工/安灯按码授权（全局角色），不按班组隔离——属设计决策而非漏洞，新班组隔离需求出现时再引入数据范围权限

## 四、测试期间的修复

| 修复 | 说明 |
|---|---|
| 路由扫描器 `@Public` 归属 bug | `@Public()` 写在上一方法体之后时会被错记到上一方法头上，漏掉 `auth/refresh`；增加"进入方法体即 flush"修正 |
| 探测路径缺前导斜杠 | supertest 报 Invalid URL；统一补 `/` |

## 五、结论与遗留

54/54 全部通过，`npx eslint test/authz-attack.e2e-spec.ts` 干净。防线的三道结构（静态扫描 → 匿名全路由 → 角色矩阵）互相兜底：新增接口忘加 `@Permissions` 会被扫描测试标红，忘删 `@Public` 会被全路由扫描标红，权限码写错会在种子比对标红。

遗留接受项（与 jwt-测试报告一致）：refresh 接口未单独限流（refresh 为 128 位随机串，暴力枚举不可行，部署期加网关限流兜底）；跑全套 e2e 时本套件应在 `npm run test:e2e` 中顺带执行（依赖同一次 `prisma migrate deploy`，自行清库，可重复跑）。
