## 用例 3 的实测结论（任务卡期望"一个成功一个 1007"）

并发 10 个 start 实测：**1 成功 + 9 个 1006**（不是 1007），log 恰 1 条。

原因：`transition()` 在**事务内二次查表**，后到的事务看到的状态已经是 IN_PROGRESS（先到者已提交），查表直接判非法 → 1006"当前状态为 IN_PROGRESS，不允许 start（允许的动作：pause / complete / cancel）"。1007（version 条件 updateMany count=0）只在"读到旧 version 但写入时已被改"的窗口出现——SQLite 写事务串行化后这个窗口几乎不存在。

判断：**保留现状**。1006 的消息更有行动性（告诉用户现在是什么状态、能做什么），1007 留给真正的 version 撕裂场景（第 37 节报工并发回写）。语义上"非法转换"就是 1006，没有偏离乐观锁设计——乐观锁仍在（version 条件更新是写安全网），只是被查表前置拦截了。
