# 测试清单

测节课用。AI 生成测试骨架后，对照本清单补齐；每条都要能在测试文件里指出对应用例。

## 覆盖要求
- [ ] 正常路径（happy path）
- [ ] 每条校验规则至少一个失败用例（必填缺失、超长、非法枚举、负数）
- [ ] 每个权限点三态：有权限 200 / 无权限 403 / 未登录 401
- [ ] 边界值：0、负数、最大值、空字符串、超长、重复
- [ ] 不存在的 id → 404
- [ ] 唯一冲突 → 409
- [ ] 涉及数量或状态的模块：并发（`Promise.all`）与幂等（同请求两次）
- [ ] 状态机：每个合法转换通过 + 每个非法转换 409
- [ ] 事务：中途失败时前面的写入已回滚

## 测试质量
- [ ] 每个测试独立，不依赖执行顺序（`beforeEach` 重置数据）
- [ ] 断言具体：断言字段值、数量、状态，不只断言 200
- [ ] 测试名描述行为，用中文："应在库存不足时拒绝领料"
- [ ] AI 生成的每个测试你都读过，删掉了"怎么都能过"的测试（没有断言、断言 `toBeDefined`、mock 了被测对象本身）
- [ ] 集成测试用独立的 SQLite 测试库，跑完可重复跑
- [ ] 单元测试只 mock 外部依赖（Prisma、HTTP），不 mock 被测 Service 自己
- [ ] 本地 `npm test` 全绿，推送后 CI 绿

## 让 AI 生成测试时的提示词要点
- 给它验收标准（`docs/acceptance/<模块>.md`）和 DTO 文件
- 明确要求："为每条校验规则写一个失败用例"、"为每个非法状态转换写用例"
- 要求用中文测试名，`describe` 按接口分组
- 生成后让它列出"没有覆盖到的场景"，你来决定补哪些
