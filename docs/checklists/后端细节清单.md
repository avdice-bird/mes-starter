# 后端细节清单

磨节课用。复制到 `docs/checklists/<模块>-后端.md`，逐项打勾，不适用的写"N/A + 原因"。每发现一个不通过项，先修再打勾。

## 输入校验
- [ ] 每个 DTO 字段都有校验装饰器：必填 / 类型 / 长度 / 枚举 / 范围 / 格式
- [ ] 分页参数有默认值和上限（page ≥ 1，pageSize 默认 20、上限 200）
- [ ] 传入不存在的 id → 404，不是 500
- [ ] 不信任前端传的 userId / 操作人，一律从 token 取
- [ ] 数量类字段拒绝负数、非整数、超出业务上限

## 数据一致性
- [ ] 编码/名称类唯一字段在 schema 有 `@unique`，重复时返回 409 + 友好消息，不是 500
- [ ] 删除：有关联数据时禁止删除（或软删），不留孤儿数据
- [ ] 多表写入在一个 `prisma.$transaction` 内
- [ ] 数量用 Int（最小单位）或 Decimal，不用 Float
- [ ] 时间统一 UTC 存储，由前端本地化显示
- [ ] 涉及状态/数量的并发修改有乐观锁（version）或行级串行化

## 错误处理
- [ ] 业务异常用 `BusinessException(ErrorCode.XXX)`，不用 `throw new Error`
- [ ] 错误码与消息符合 `CLAUDE.md` 错误码表
- [ ] 不向前端泄漏堆栈、SQL、内部路径
- [ ] 未捕获异常有日志（含请求 id、用户 id）

## 权限与安全
- [ ] 每个 Controller 方法都有 `@Permissions('模块:动作')` 或明确的 `@Public()`
- [ ] 响应里没有密码哈希、refresh token、内部字段
- [ ] 文件上传限制类型与大小
- [ ] 查询参数不拼接进原生 SQL

## 审计与日志
- [ ] 创建/修改有 createdBy / updatedBy / createdAt / updatedAt
- [ ] 关键业务操作（下达、报工、入库、状态变更）写审计日志
- [ ] 状态类对象有状态变更记录表

## 接口设计
- [ ] Swagger 上每个接口有 summary，每个 DTO 字段有描述
- [ ] 列表支持分页、排序、关键字筛选，参数名统一
- [ ] 响应结构统一 `{ code, message, data }`
- [ ] 同一资源的接口路径符合 REST（`GET /materials/:id`、`POST /work-orders/:id/release`）
