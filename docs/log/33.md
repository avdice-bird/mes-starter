## 自查结果

- `transition()` 状态更新 + log 写入同一个 `$transaction`：✅（回滚测试锁定）
- 乐观锁覆盖所有写路径：transition ✅；**PATCH plan 漏了 → 本节补上**（任务卡预判正确）
- 事务内 HTTP/长耗时：✅ 无
- SQLite 并发写：PrismaService 已设 `busy_timeout=5000` + `WAL`（骨架预置），✅

## 回滚测试的意外收获（比结论本身更有价值）

写"mock log 抛错断言状态未变"的测试时，第一版替身把事务内操作路由到了**顶层 Prisma 客户端**而非 `tx` 事务客户端——测试全绿但回滚根本没发生（update 各自自动提交）。也就是说：**测试替身违反事务语义时，测试照样能"通过"**。修正替身（Proxy 透传到真实 tx）后回滚断言才真正生效。这条写进 ADR 后果区：事务回调里出现 `this.prisma` 而不是 `tx` 就是红旗，评审时一眼要能抓出来。
