# 互测① 越权攻击记录（第 9 节 · 自攻版）

- 发现人：逍遥（自攻：没有配对同学，按任务卡 8 个攻击项对自己的项目打一轮）
- 攻击身份：`operator`（操作工，无任何权限码）/ 匿名
- 日期：2026-09-18

| # | 攻击项 | 结果 | 说明 |
|---|---|---|---|
| 1 | 隐藏按钮对应的接口直接 curl | ❌ 被拦 | operator `POST /api/users` → 403 code 1003（前端 v-permission 只是体验，PermissionsGuard 每请求查库） |
| 2 | 改 URL 里的 id 访问别人数据 | ❌ 被拦（横向隔离除外） | `GET /users/:id`、`GET /roles/:id` 等都有权限码；**同权限码用户之间没有行级数据隔离**，属业务范围问题，记入遗留（MES 单租户场景可接受） |
| 3 | 改 localStorage 权限列表让按钮出现 | ❌ 无效 | 前端 store 改了只影响显示；后端守卫每次请求按数据库实时校验（ADR-002） |
| 4 | 给自己分配 admin 角色 | ❌ 被拦 | `PUT /users/:自己id/roles` 直接 403（"不能修改自己的角色"，比"不能给自己加 admin"更严） |
| 5 | 用过期/伪造的 token | ❌ 被拦 | 伪造 token 签名校验失败 → 401 code 1002；过期同理 |
| 6 | 用 admin 的 refresh token | ❌ 被拦 | refresh 轮换：旧 token 已 revoked；再次使用 → 401；且 refresh 是随机串不可伪造 |
| 7 | 找没有 @Permissions 的接口 | ⚠️ 有 3 个但安全 | `/auth/logout`、`/auth/me`、`/auth/refresh`：只要求登录，操作范围仅限 token 本人，无提权面；扫描测试把它们列入显式白名单，新增无码接口会被测试拦住 |
| 8 | 菜单接口返回无权菜单 | ❌ 无效 | `GET /api/menus` 需要 `menu:view`（operator 403）；`/auth/me` 只返回按权限码过滤并剪枝后的菜单树 |

**结论**：8 项攻击无有效越权。过程中顺手修复的两个非攻击项问题：
1. 无角色用户的菜单树会显示空的「系统管理」目录（用例 6 发现）→ `visibleTree` 增加空目录剪枝；
2. `nest-cli.json` 的 `deleteOutDir: true` 在本机触发 safe-delete hook 批量删除拦截（第二次启动 dev server 必挂）→ 已关闭。
