## 排产算法伪代码（任务卡要求：先给伪代码确认再写代码）

```
schedule(工单列表, 产线列表, 已占用产能, 起始日):
  可排产线 = 产线.filter(启用 && 日产能 > 0)
  排序 = 优先级 asc → 交期 asc → 创建时间 asc     # 稳定、可复现
  产能占用表[产线][日期] ← 已占用产能（已开工工单）
  for 工单 in 排序后的工单列表:
    if 工单.数量 <= 0:                 跳过("数量必须大于 0")
    if 指定产线 不在 可排产线:          跳过("产线不可排")
    候选 = 指定产线 ? [它] : 可排产线
    for 产线 in 候选:
      天数 = ceil(数量 / 产线.日产能)
      起始 = 从起始日找第一段连续"天数"个空闲日
      取（最早开工，并列取最早完工）的方案
    if 无方案: 跳过("窗口内产能不足")
    占用产能表; 写 plannedStart/plannedEnd
    isDelayed = plannedEnd > 订单.交期
```

## 我做了

- 规格：`docs/acceptance/schedule.md` 12 条验收项 + 排产口径。
- 两个设计判断：
  1. 拆分守恒在 Service 校验"数量之和 === 订单 qty"，不在 DB 层做——拆分与订单写入在同一事务，代码保证不变量足够；
  2. 已开工工单不重排不靠"跳过"实现，而是调用方只把 `status=CREATED` 传给纯函数，已开工产能由 `buildExistingLoad()` 均摊到日扣掉。
- 跑通验证：建 3 订单拆 5 工单排产；种子产线日产能大，全部排到首日完工、延误用例不触发，改用两条小产线（100/50）验证出 1 张延误（300 件 3 天，10-15 → 10-17 > 交期 10-14）。

## AI 做了

- schema 两表 + 迁移（SQLite 不支持 `ALTER TABLE ADD CONSTRAINT`，首跑失败半程，手工 DROP 半成品表 + `migrate resolve` 后重放成功——迁移 SQL 里外键要内联在 CREATE TABLE）。
- 模块三件套（订单 Service / 排产 Service / 工单只读 Service + 三 Controller）+ 算法独立纯函数文件 `scheduler.algorithm.ts`（28 节单测对象）。
- 前端三 tab 页（订单/工单/排产）+ `work-order/WorkOrderList.vue` + `api/schedule.ts`。
- 返工 2 次：`ScheduleRunResult` 类型误从算法文件导入（应从 @mes/shared）；拆分对话框模板一个引号笔误被 vue-tsc 抓住。

## 发现的问题

- 未指定产线的工单会被大产能产线一次吃完，演示延误必须限小产线——排产结果依赖产线配置，验收演示前先看数据。
- 前端"一键排产"是覆盖式重排（CREATED 全部重算），这是设计口径，不是 bug。

## 遗留

- 排产窗口默认 90 天、窗口内产能不足才跳过；批量订单下"最早空闲"可能次优（真 APS 是另一门课）。
- `WorkOrder.version` 乐观锁字段已留，第 30 节状态机用。
