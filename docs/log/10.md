- 日期：2026-09-20
- 目标：写可复用的 CRUD 生成提示词模板，用它一次生成数据字典模块
- 用时：课内 40 分钟 / 课外约 90 分钟

## 我做了

- 写 `docs/prompts/crud-module.md` v1：输入（字段表/权限前缀/软删）、必须遵守、输出清单、**生成顺序（分四批）**、**禁止**段，另加"完成后自检"段。
- 用模板生成字典模块时按批次把关：
  - 第一批（schema+DTO）确认了唯一约束设计：Dict.code 全局 `@unique`；DictItem 用 `@@unique([dictId, value])` **分组唯一**（value 跨字典可重复是业务要求）；
  - 发现 v1 模板漏了"下拉提供方"场景——字典要给所有业务页面供下拉，但管理权限码 `dict:view` 不该挡住业务页面取选项 → 补了 `GET /dicts/code/:code/options`（登录即可、只读、扫描白名单登记）。

## AI 做了

- 按模板四批生成：schema/DTO → Service/Controller/Module/种子 → 前端 api/DictList.vue/useDict → 测试（单测骨架 + e2e + 矩阵 17 行）。
- 返工 2 次：①矩阵里"删有项字典"期望 200 实际 409（这正是业务规则，期望值改 409 并注释因果）；②shared 类型没先 build 导致 web 编译报 DictRow 缺失——模板 v2 的自检段补了"先构建 @mes/shared"。

## 跑通验证（浏览器实测）

admin 登录 → 系统管理出现"数据字典"菜单 → 新建字典 work_order_status → 抽屉里加 3 个字典项（进行中/已完成/已取消）→ `GET /api/dicts/code/work_order_status/options` 返回 3 个启用项。✅
