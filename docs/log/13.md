# 第 13 节 · 物料 · 【建】物料 / 分类 / 单位 + Excel 导入导出

- 日期：2026-09-22
- 目标：物料主数据跑通，能用 Excel 导入 200 条物料
- 用时：课内 40 分钟 / 课外 60 分钟

## 我做了
- 写了 schema 三张表：Unit（code/name/status）、MaterialCategory（parentId 树）、Material（code 唯一、category/unit 外键、type 枚举、safetyStock 可选、isDeleted 软删）
- 决定了权限分配：planner 给 material:* 和 category:*，单位只给 unit:view（单位是管理员维护的全局字典）；operator/qc/maintainer 暂不给
- 决定了导入接口形态：`POST /materials/import` multipart（字段 file）、`GET /materials/export`、`GET /materials/import-template`
- 基础数据菜单挂 `/base` 目录：物料、分类、单位三页

## AI 做了
- 用 CRUD 模板生成了 unit、material-category、material 三层（controller/service/dto/前端页面/api 封装）
- 单独生成了导入导出：exceljs 解析（按表头名取列、跳空行、保留行号）、模板与导出文件生成、zip 魔数校验
- 返工 2 次：一次 DTO import 路径深度写错（../../ 少一级），一次 exceljs 的 `xlsx.load` 类型与 Node Buffer 泛型不兼容（`Buffer extends ArrayBuffer` 的接口重声明），最后用 `unknown` 断言绕开

## 发现的问题
- AI 初版把编码正则写成 `[A-Za-z0-9_]`，而业务编码天然带连字符（CAP-0402-104），导入全报错——正则改成 `[A-Za-z0-9_-]` 并同步 DTO/前端/校验函数三处
- 校验函数里 `v in MATERIAL_TYPE_LABELS` 查的是 key 不是 value，"原料"这种合法标签被误判非法；改成 `Object.values().includes`
